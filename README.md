# 轻量聊天室

这是我用 Python 和 Vue 从零搭的一个网页聊天室。注册个账号、建个群、把邀请码发给朋友，就能一起聊天。消息实时到达，刷新页面或者断网重连之后，聊天记录一条不少。

前后端都在这一个文件夹里，不用装数据库、不用 npm、不用打包工具，一条命令跑起来，电脑和手机都能开。

## 它能干什么

**账号**

- 注册和登录，密码在数据库里是加密过的，搜不到明文
- 16 个表情头像任选，选过会记住
- 没登录就看不到任何群

**找群和建群**

- 建群会自动生成一个 6 位邀请码
- **私密群**：你没邀请的人，根本看不到你的群，也进不来
- 允许建同名群，靠邀请码区分（列表里会显示每个群的码）
- **公开大厅**是个群广场：游戏群、八卦群、二次元群、运动群、学习群、音乐群，一共六个。
  每个群一个格子、风格各不相同，格子里还有用纯 CSS 画的小插画（掌机的画面在滚、唱片在转、篮球在弹……）。
  点进去**可以先看再决定加不加**——公开群不用邀请码，谁都能看聊天记录，想说话再点「加入本群」。
  这些群是"系统建的"，所以谁都解散不了，但人人都能退
- 普通成员可以**退群**（自己退出，群还在，别人照样聊；以后想回来再用一次邀请码就行）
- 房主可以**解散**群，解散后聊天记录一起清掉，群里其他人会收到通知并自动退出（房主自己不能退群，跟微信群一样）
- 别人拿到码，或者点你发的邀请链接，就能直接进群

**聊天**

- 消息实时到达，不用刷新
- 顶部显示"N 人在房间里"，有人进出立刻更新
- 对方打字时底部出现"🐼 小明 正在输入..."，停手三秒消失
- 自己发的消息下面显示已读状态：**全都看了显示"已读"**；只有一部分人看了就把名字报出来（"小明、小红 已读"）；人多了自动缩成"A、B、C 等 5 人已读"；一个都没看显示"未读"
- 断网会自动重连，重连后把漏掉的消息补回来

**右键消息的小菜单**

在自己发的消息上点右键，会弹出一个小菜单：

- **撤回**：撤完别人那边显示"这条消息已撤回"
- **查看已读**：弹窗里分两堆列出"谁已读、谁未读"，自己不算在内
- **复制**：把这条消息的文字抄到剪贴板（手机上 http 页面也能用，见后面的坑）
- **引用**：发下一条消息时带上它，气泡里会显示一块灰底的引用小字

复制和引用对**所有人**的消息都能用，撤回和查看已读只对自己发的消息显示。

**拍一拍**

- 用鼠标（手指）**快速双击某个人的头像**就能拍他一下，3 秒冷却，不能拍自己
- 每个公开群的特效都不一样，而且是按群名自动匹配的：
  - 游戏群：准心从屏幕正中冒出来，瞄准、缩小、锁定在头像上，最后开火闪一下
  - 八卦群：一个西瓜从天而降砸中头像，裂成几瓣飞出去
  - 二次元群：两根大葱当双马尾扎在头上，像荧光棒一样绕圈甩
  - 运动群：篮球从屏幕中心飞过来，拍地弹跳后旋转着飞走
  - 学习群：给头像盖一朵小红花印章，停四秒再淡掉
  - 音乐群：音符往上飘，头像底下贴一排均衡器音柱
  - 自己建的私密群：一巴掌 + 白色扩散圈 + "拍了拍"三个字
- 不管你在滚动消息列表还是没加载过那条消息，特效都会**钉在你双击的那个头像上**，不会飘错位置

**新消息提醒**

- 房间列表上的红点数字实时往上跳（别人发一条就 +1，不用刷新）
- **不管你打没打开那个群，来消息都会有红点**
- 提示音的原则是"**你看得见就不响，看不见才响**"：正盯着这个群看的时候不响（消息就在眼前）；别的群来消息、或者人切到别的页面（手机锁屏也算）时就响一声"叮"
- **人切到别的标签页时**，浏览器标签页标题会开始一闪一闪地显示"💬 你有新的消息"，直到你切回来才停
- 提示音和标签页闪烁都由左上角 🔔 一键开关；关掉就全关
- 人正看着聊天室页面时标签页不闪（本来就看得见）

**外观**

- **白天 / 夜间模式**：登录后左上角"我"卡片里有个 🌙，点一下全站换成深色版；登录页右上角也有一颗浮着的圆按钮。选过一次会记住
- 现在是"奶油手帐贴纸风"：奶油纸底、粗描边、硬阴影，像贴在手帐上的贴纸
- 手机上是全屏，电脑上是居中的卡片，一套样式自动切换

顺带说下性能。我写脚本模拟过几十个人同时挤在一个群：

- 建立 50 条连接：0.20 秒
- 一条消息广播给 50 个人：0.061 秒，一个都没漏
- 50 个人各发一条：第一个人完整收到 50 条，一共 2.02 秒，平均每条 40 毫秒

40 毫秒大概是人眨一次眼的七分之一。

## 怎么跑起来

需要 Python 3.9 以上。先确认一下：

```bat
python --version
```

然后在项目文件夹里开一个命令行窗口，依次敲：

```bat
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

第二句敲完，命令行前面会出现 `(venv)`，说明虚拟环境生效了。要是没出现，后面装的包就会装到别的地方去。

装完就可以启动了。**最简单的办法是双击 `start.bat`**，也可以手动敲：

```bat
venv\Scripts\activate
python main.py
```

看到 `Uvicorn running on http://0.0.0.0:8000` 就成了。那个黑窗口不要关，关了服务就停了。

> 端口和监听地址写在 `config.py` 里（`PORT = 8000`、`HOST = "0.0.0.0"`），想换端口改那一个文件就行，改完重启生效。
> 也支持老办法 `python -m uvicorn main:app --reload --host 0.0.0.0 --port 8000`，两种方式效果一样。

然后开浏览器：

- 电脑上打开 `http://127.0.0.1:8000`
- 手机连同一个 WiFi，打开 `http://电脑的IP:8000`

电脑的 IP 用 `ipconfig` 查，找"IPv4 地址"那行。注意换过 WiFi 之后 IP 会变，之前存的地址可能就失效了。

想直接调接口的话，`http://127.0.0.1:8000/docs` 这个地址是 FastAPI 自动生成的一张接口清单，点开就能填参数发请求，不用额外装 Postman。

## 我是怎么验证的

按下面走一遍，基本就能确认所有功能都正常：

1. **注册登录** — 注册一个账号，退出再登录，密码还是那个
2. **建群** — 填名字点建群，自动进群，右上角能拿到邀请码
3. **邀请别人** — 用另一个账号（或手机）输入邀请码，或者直接点邀请链接，直接进同一个群
4. **互发消息** — 一边发，另一边不用刷新就能看到
5. **已读未读** — 对方看完消息后，你这边消息下面会变成"已读"
6. **右键菜单** — 在自己发的消息上点右键：撤回后两边都变"已撤回"；查看已读能看到谁读了谁没读；复制能粘出来；引用后发一条，气泡里会出现灰底引用块
7. **撤回** — 点自己消息下面的"撤回"一样有效
8. **拍一拍** — 双击别人的头像，两边都播特效（游戏群是准心、二次元群是甩葱……）。**必须两个窗口或两台设备**，自己看自己没提示
9. **刷新不丢** — 按 F5，聊天记录还在
10. **断线重连** — 把服务器关掉再打开，页面自己重连，断线期间的消息补回来
11. **"正在输入"** — 两个方向都要试：电脑打字手机看，手机打字电脑看
12. **群是私有的** — 开第三个账号，它的列表里不应该出现前面那个群
13. **标签页提醒** — 开两个标签页，聊天室放一边切走，让别的账号在**任意群**（包括你没打开的那个群）发消息，标签页标题应该开始闪"你有新的消息"；把铃铛点成 🔕 再试一次，应该不闪
14. **夜间模式** — 点 🌙 换深色，再开一次页面应该还是深色

第 11 条多说一句：自己打字的时候，自己这边不会显示"我正在输入"，这是故意的，微信也是这样。所以必须一边打、另一边看才看得见效果。

## 文件夹里都有什么

```
chat_room/
├─ main.py           后端入口：接口 + 实时转发
├─ db_helper.py      数据库相关：建表、存消息、账号、邀请码、已读进度
├─ config.py         端口、文件路径这类配置，改这里就行
├─ start.bat         Windows 下双击启动
├─ requirements.txt  依赖清单
├─ chat.db           数据库文件，第一次运行自动生成
└─ static/
   ├─ index.html     页面结构
   ├─ app.js         页面逻辑
   ├─ style.css      样式（顶部一整块"主题变量"，白天/夜间两套值）
   └─ vue.global.prod.js  Vue 3，直接从本地加载
```

数据库有四张表：

```
users         账号：用户名、加密后的密码、盐、头像
rooms         群：名字、创建时间、邀请码、谁建的、是不是公开群
room_members  谁加入了哪个群、读到第几条消息了
messages      消息：属于哪个群、谁发的、内容、时间、头像、是否撤回、引用了哪条
```

两张表是"关键设计"，说一下为什么必须有：

- `room_members` 是**群私有**的关键——群列表只返回你在这张表里有记录的群，别人没你的码就永远看不到
- `last_read_id`（在 `room_members` 里）是**已读未读**的关键——记的是"这个人读到第几条了"，跟消息编号比大小就知道他看没看

## 为什么选这几个技术

- **后端用 Python + FastAPI**：自带 WebSocket，还白送一个接口调试页面；Python 读起来也最像人话
- **前端用 Vue 3**：数据一变界面就跟着变，不用自己手动改页面元素
- **数据库用 SQLite**：Python 自带，不用装数据库服务，一个文件就是整个库
- **服务器用 Uvicorn**：一条命令启动，页面和接口一起提供

整个项目只装两个包：`fastapi` 和 `uvicorn`。没有构建工具、没有 npm、没有数据库服务。

密码加密、随机邀请码、登录令牌用的都是 Python 标准库（`hashlib` / `secrets`），一样没多装。

Vue 我也下载到了项目里（`static/vue.global.prod.js`），不走 CDN。之前踩过一次坑，后面会说。

## 接口说明

除了登录和注册，**所有接口都要在地址后面带上 `?token=xxx`**（登录时发回来的那个令牌），不然服务器不知道你是谁，会返回 401。

- `POST /api/register` — 注册，返回令牌
- `POST /api/login` — 登录，返回令牌
- `GET /api/rooms` — 列出**我加入过**的群
- `POST /api/rooms` — 新建群，body 是 `{"name": "群名"}`
- `POST /api/join` — 用邀请码进群，body 是 `{"code": "邀请码"}`
- `GET /api/hall/rooms` — 列出公开大厅里的群（不用加入也能看）
- `POST /api/rooms/{群id}/join` — 加入当前正在看的这个公开群
- `POST /api/rooms/{群id}/leave` — 退群（只删自己的成员记录，群和消息都留着）
- `POST /api/rooms/{群id}/dismiss` — 解散群，只有建群的人能用
- `GET /api/rooms/{群id}/messages` — 取历史消息（不是成员会返回 403）
- `GET /api/hello` — 确认后端还活着
- `WS /ws/{群id}?token=xxx` — 群里的实时通道，收发消息都走它
- `WS /ws/notify?token=xxx` — 通知专线，登录后一直连着，用来收其他群的未读提醒

群里那条 WebSocket，前端发给服务器的有这几种：

```json
{"type": "message", "content": "你好", "quote_id": 0}  ← 发消息（不用传用户名，服务器用令牌自己查）
{"type": "typing"}                            ← 我正在打字
{"type": "recall", "id": 123}                 ← 撤回某条消息
{"type": "read", "last_id": 123}              ← 我读到了第 123 条
{"type": "poke", "target": "小明", "mid": 88} ← 拍一拍某人（mid 是双击的那条消息的编号）
```

服务器推回来的有这几种：

```json
{"type": "message", "id": 1, "sender_name": "小明", "content": "你好", "avatar": "🐱", "recalled": 0, "quote_id": 0, "created_at": "..."}
{"type": "typing",  "sender_name": "小明", "avatar": "🐱"}
{"type": "online",  "count": 3}
{"type": "recall",  "id": 123}
{"type": "read",    "reads": {"小明": 118, "小红": 115}}
{"type": "poke",    "from": "小明", "target": "小红", "avatar": "🐱", "mid": 88}
{"type": "dismissed"}                         ← 这个群被房主解散了
```

区别是：

- `message` 是真消息，**先存数据库再转发**，所以刷新不会丢
- `typing` 不存数据库，也**不发回给本人**，对方停手三秒就没了
- `online` 是在线人数，有人进出时推一次
- `recall` 是谁撤回了哪条，收到后把那条显示成"已撤回"
- `read` 是群里所有人的已读进度，收到后用来判断"我的消息对方看了没"
- `poke` **不存数据库**，纯转发——拍一下就过去了，不留聊天记录
- `dismissed` 收到后要立刻退出这个群

通知专线（`/ws/notify`）只推一种：

```json
{"type": "unread", "room_id": 3, "unread": 5}
```

意思是"第 3 个群你有 5 条没读"。不管你有没有打开那个群，它都会推，红点和标签页提醒就靠它。

## 它到底是怎么工作的

说白了就三件事：

1. **实时**：每个人进群时跟服务器拉一条 WebSocket 连接。谁说话，服务器就发给群里所有人。
2. **不丢消息**：每条消息都是**先写进数据库，再转发出去**。进群时先把历史拉出来，再连实时通道。所以刷新、断网都不怕。
3. **断了能自己接上**：连接断了会自动重连，3 秒试一次，连上后再拉一次历史补齐。

代码里有几处写法，光看代码会有点莫名其妙，记一下为什么：

- **`room_conns` 字典** — 记"哪个群有哪些人在线"，决定消息转发给谁
- **广播前先 `list()` 复制一份** — 防止遍历的时候有人退出，导致遍历出错
- **连接清理写在 `finally` 里** — 不管怎么断都删掉，不然名单里会留下永远发不出去的死连接
- **发消息不传用户名** — 发送者身份一律用令牌查，不信前端传的，防止冒名
- **拍一拍也要校验身份** — 拍人转发的是"谁拍的谁"，同样以令牌为准，不信前端
- **撤回前双重校验** — 确认"是你发的"且"在这个群"，两条都满足才给撤
- **撤回和退群只打标记（或只删自己那条记录），不删数据** — 删了的话别人刷新会凭空少一条，序号对不上
- **前端按消息 `id` 去重** — 兜底，防止同一条消息显示两遍
- **连新线之前先关旧线** — 保证一个页面只有一条连接，从根上避免消息重复
- **输入框监听四个事件** — `input` + 两个 composition 事件 + `keydown`。手机拼音选词时根本不发 `input` 事件
- **静态文件带版本号** — `app.js?v=42`，改完代码数字加一，浏览器就会当新文件下载
- **颜色全部写成变量** — 夜间的样式只在 `style.css` 末尾换一套变量值，不重写任何一条样式
- **时间用 Python 生成** — 数据库自带的 `CURRENT_TIMESTAMP` 是 UTC 时间，比北京时间晚 8 小时

## 我踩过的坑

这部分是我做的时候真实遇到的问题，按"现象 → 查出来的原因 → 最后怎么改"记的。

### 界面和前端

**1. 页面一打开全是 `{{ currentRoom.name }}`，两个画面还叠在一起**

查下来是 Vue 没加载成功——那会儿它是从国外 CDN 拉的，网络不通就失败了。Vue 一挂，控制"显示哪一屏"的 `v-if` 也就失效了，本该二选一的两个画面就同时渲染出来了。

后来把 Vue 下载到项目里改成本地引用，断网也不影响了。

**2. 发一条消息，页面上出现两条**

一开始以为是服务器发重了，写脚本直连服务器测了一遍，发现服务器每次只广播一次。

真正的原因是页面上挂了**不止一条连接**：断线自动重连时旧的那条没关掉。服务器广播一次，两条连接各收到一次。

改法是连新线之前先把旧的彻底关掉（关之前要先摘掉它的 `onclose`，不然关闭这个动作又会触发一次自动重连，没完没了）。另外又加了按 id 去重的保险。

**3. 用中文输入法打字，按回车消息发了两次**

输入法里的回车是在**选词**，不是"发送"。所以在发送函数开头加了一句：正在组字就忽略这次回车。

**4. 手机打字，电脑收不到"正在输入"，反过来却正常**

手机上的拼音输入法分两步走，在候选词上屏之前，那些字母没真正进输入框，浏览器也就**不触发 `input` 事件**，通知压根没发出去。电脑键盘没这个中间步骤，所以反向正常。

最后在输入框上额外监听了 `compositionstart`、`compositionupdate` 和 `keydown`——这几个是专门为输入法准备的。

> **还剩下的已知限制**：拼音**没上屏**那一刻，网页是拿不到内容的（浏览器限制，不是代码问题），
> 所以手机上要等文字真正进入输入框，对方才会看到"正在输入"。
> 部分安卓输入法连 composition 事件都不发，这种设备上同样要等上屏才有提示。
> （试过再加 `focus`/`blur` 心跳做保底，能做到一点输入框就提醒，但代价是"光点不打字也会显示正在输入"，最后没采用。）

**5. 改了前端代码，手机上没变化**

浏览器缓存。电脑上 Ctrl+F5 还能解决，手机上清缓存挺麻烦。后来给引用的文件加了版本号（`app.js?v=42`），改一次加一，普通刷新就行。

**6. 自己打字，看不到"正在输入"**

这不是 bug，服务器转发时故意跳过了本人，微信也是这样。要两个窗口一边打一边看。

**7. 换了个群，之前群的已读状态倒退回未读了**

现象是我从 A 群切到 B 群，A 群里我明明看过的消息又变成"未读"（对别人来说）。

查出来是**消息编号是全数据库统一往下排的**，不是每个群各排一份。切群的时候旧连接没先挂断，于是"我读到 B 群第 120 条"这条通知，是从 A 群那条线上发出去的——A 群的人收到 120，比他们看到的编号还大或者对不上，已读就乱了。

改法：每次打开一个群之前，先把上一条连接彻底关掉，同时清空页面上的读进度。

**8. 查看已读时，未读名单里冒出一个叫"系统"的人**

公开大厅那六个群的创建者记的是"系统"，而它也被当成普通成员登记进去了，所以统计已读时把它算进来了。改成统计时跳过它。

**9. 电脑上双击头像拍人，会弹出浏览器自带的选择/复制小工具条**

双击的默认行为是"选中文字"，浏览器就顺势弹工具条了。三层修复：给头像加"禁止选中"的样式、按下鼠标时直接把默认动作拦掉、触发拍一拍时把已选中的文字清掉。

**10. 拍一拍的特效落错头像，而且滚动消息列表时特效不跟着走**

两个问题其实是同一个根源：特效是按"当时的位置"画死的。

- 落错：以前只能按"这个人最后一条消息的头像"找位置，可我双击的可能是他中间某条消息。后来把双击的那条消息的编号一起发给服务器，收到的所有人才能锁到**同一个**头像上
- 不跟随：改成先造一个 0 宽 0 高的"锚点容器"钉在头像中心，特效元素全画在它里面，然后每帧跟着头像挪一次位置。滚动时特效就跟着头像走了

**11. 开了夜间模式，对话和输入框里的字看不清**

变量套变量惹的祸。墨黑色我是这么写的：`--ink: rgb(var(--ink-rgb))`，夜里只改了 `--ink-rgb`，以为 `--ink` 会自动跟着变。

其实 CSS 的规矩是：**里层的变量在"声明它的那个元素"上就先算好了**，算完的值再传给后代。所以 body 上改 `--ink-rgb`，`--ink` 还是白天的深墨黑，深色字压深色底，自然看不清。

最后在夜间那套变量里把 `--ink` 重新声明了一遍，让它当场用新值重算。

### 后端和数据库

**12. 所有接口都 404，只有页面能打开**

原因是把静态目录挂载写在了接口前面。请求是从上往下匹配的，先挂了静态目录，所有请求都被当成"找文件"，接口永远走不到。挪到最后就好了。

**13. 消息时间比实际晚了 8 小时**

SQLite 自带的 `CURRENT_TIMESTAMP` 存的是 UTC 时间。改成用 Python 取本机时间再存。

**14. 做头像功能时，给消息表加了一列**

数据库里已经有表了，直接改建表语句对旧表不起作用。所以我在建表函数里加了一段：先查表里有哪些列，缺了就补上。不用删数据库，之前发的消息也都还在。（后来加邀请码、已读进度、撤回标记、引用编号，用的都是同一招。）

**15. 排查"消息重复"时发现的隐患**

连接名单只在"正常关闭页面"时才把人移除。有人直接断网或关电脑，那条连接就会一直留着变成幽灵，服务器每次广播都白发给它一次。改成了不管怎么断都清理。

### 做完功能之后发现的

**16. 我没邀请别人，别人却能看到我的群**

因为接口是把**所有群**都返回的。加了 `room_members` 表记下"谁加入过哪个群"，群列表改成只返回自己加入过的。别人没你的码，就永远看不到。

**17. 输入邀请码后连不上群，一直转圈**

真凶不是邀请码，是**登录凭证失效了**。凭证存在服务器内存里，服务器一重启就清空，但浏览器里还留着旧的，页面以为自己还登录着，于是 WebSocket 一直被拒绝，表现就是永远卡在"连接中..."。

改法：连接被服务器拒绝时（代码 1008），不再傻等重连，直接提示"登录失效，请重新登录"。

**18. 手机上点"复制邀请链接"没反应**

浏览器只允许 https 网页用剪贴板，咱们是 `http://192.168.x.x`，所以被禁了。加了备用方案：先试新接口，失败就改用一个隐藏的输入框加老式复制命令，在 http 下也能用。

**19. 把邀请链接粘进输入框，只剩 `http:/`**

输入框设了最多 6 个字符（配合 6 位邀请码），链接被截断了。改成不限长度，而且代码会自动识别：粘进来的是链接就把里面的邀请码抠出来。

**20. 别的群来消息，只有红点动，标签页不闪、也不响**

提醒只在"群里那条连接"里触发，可我人根本没打开那个群，那条线压根没连上。真正收到的是通知专线，而它只更新了红点。

改法：通知专线收到未读消息时，也叫一次提醒。现在不管你打没打开那个群，只要有新消息，红点、提示音、标签页闪烁一起上（当然，还是得人在别的标签页、铃铛开着）。

> 第 15 条没造成过你能看到的问题，是我做别的功能时顺手发现并加固的，所以没印象很正常。

## 出问题了先看这里

**手机打不开页面**

先确认服务器那个黑窗口还开着。然后确认手机和电脑连的是同一个 WiFi。地址要用 `http://` 开头。还不行就重新 `ipconfig` 查一次 IP——换过网络 IP 是会变的。最后可能是防火墙拦了，启动服务器时 Windows 弹过"是否允许访问"的话要点允许，或者在防火墙里放行 8000 端口。

**卡在"连接中..."，或者群列表是空的**

多半是服务器重启过，令牌失效了。点左上角"退出登录"重新登一次就好。这是令牌存在内存里的代价，不是故障。

**页面显示一堆 `{{ }}`**

说明 Vue 没加载到。现在项目里已经有本地的 Vue 了，重新打开一次页面就好。

**改了代码没生效**

后端的 `.py` 改了会自动重启（启动命令里有 `--reload`）。前端改了要看一下 `index.html` 里的版本号有没有加一，加了的话普通刷新就行。

**"正在输入"看不到**

先确认是不是"自己打自己看"——那样永远看不见。要两个窗口或者电脑加手机，都进同一个群，一边打字不发送，另一边才看得到。手机打字电脑没反应的情况已经修过了（见坑 4）。

**拍一拍没反应**

确认是**快速双击别人的头像**（350 毫秒内点两下），不能拍自己，而且有 3 秒冷却。另外自己这边不会显示"自己拍了别人"的提示，要在另一个设备上才看得到特效。

**标签页不闪**

先确认铃铛是 🔔 不是 🔕，再确认当时**人不在聊天室这个标签页上**（切到别的标签页或别的窗口）。人在页面上时是不会闪的，这是故意的。

**消息重复显示两条**

已经修过了。万一还出现，先重新打开页面看看。

**群最多能有几个**

群数量没有上限，一个 SQLite 文件能存海量数据，只受硬盘限制。同一群同时在线的人数也没有写死限制，我实测 50 个人很流畅。

**想清空数据库重来**

删掉 `chat.db`，下次启动会自动建一个空的（公开大厅那六个群也会自动重建）。

> 注意：测试过程中要清数据的话，只删账号、消息、成员记录就好，**别删 rooms 表**——那六个公开群是系统资产，删了得重启服务器才会回来。
